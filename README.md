## 开始使用与复现

1. 在本页补充项目信息，在 docs/ 记录研究方案及版本。
2. 按 data/README.md 完成变量字典，说明数据来源与授权获取方式。
3. 在 analysis/README.md 写明软件版本、输入、运行顺序和输出；本地数据路径通过未跟踪的配置管理。
4. 将可公开的结果放入 outputs/，记录对应分析脚本、数据版本及核对状态。
5. 在 manuscript/ 中组织论文并引用已核对的结果。

目前没有可运行分析；后续提交脚本时同步补充复现说明。

## 协作方式

- 用 Issue 明确任务、交付物和验收标准；不要粘贴个体数据。
- 每项修改使用独立分支，通过拉取请求（PR）说明修改原因及核对方法，再合入 main。
- 文件采用含义明确的名称；版本由 Git 记录，避免“最终版2”等命名。
- Word 等二进制文件尽量由一人同时编辑，交接前先同步最新版本。
- 方案或统计方法变更在 docs/decisions.md 留痕；不得静默覆盖既定分析计划。

## 公开材料边界

本仓库为公开仓库。仅提交经授权公开的材料；不提交患者级数据、身份映射、联系方式、未脱敏伦理附件或凭据。去标识化数据也需单独判断是否获准公开。

原始数据存于机构批准的受控位置，本仓库仅记录不含敏感路径的获取流程和版本标识。.gitignore 只是误提交防护，不能代替提交前检查，也不会移除已经跟踪的文件。

## 撤销与许可

初始化结构通过独立PR提供；未合并时可关闭PR，合并后可用 revert 提交撤销结构变更，保留历史。首次README提交是空仓库的起点。

暂未选择开源许可证；公开可见不代表获得再分发或再利用授权。发布代码或材料前由项目负责人确认许可及第三方权利。
